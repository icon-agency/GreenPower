# LESSONS.md

Running log of corrections. Each entry prevents a future mistake.
Read before starting work. Append (don't edit) when something goes wrong.

- `text-wrap: pretty` is the site-wide default (set on `body`, inherits to every text node including headings). The hero h1 (`.hero__title`) is the lone exception, kept on `text-wrap: balance` for its display headline.
- Wire text wrapping into base typography or a shared mixin. Do not re-apply it per component.
- Raster images must ship with `srcset` + `sizes`. The page scales fluidly above the `wide` breakpoint (clamp on root font-size, container max grows to 1600px), so single-resolution images will look soft on large displays.
- Hero (and any rounded, full-bleed panel with a GPU-composited pseudo-element): use `overflow: hidden`, not `overflow: clip`. `overflow: clip` skips the Block Formatting Context so the compositor is not guaranteed to clip the promoted layer flush with the edge during resize repaints — a sub-pixel strip of the gradient background bleeds through on the right. Also give the `::before` a small horizontal overbleed (`inset: … -2px`) as insurance against fractional-pixel hero widths.
- Background parallax layers (`data-parallax-bg`) must compute their viewport offset from `el.getBoundingClientRect()` directly — **never** via `el.offsetParent`. The hero section has no positioned ancestor, so `offsetParent` resolves to `<body>` (full page height ~4800 px), producing an offset ~20× too large that overshoots the parallax buffer and exposes the gradient background at the bottom of the hero. Foreground layers (`data-parallax`) are `position: absolute` inside a positioned container, so `offsetParent` is correct for those.
- Cropped image parallax needs a height-based bleed buffer. If the image itself moves inside a rounded/hidden container, extend it beyond the mask before translating so card or panel background cannot show at the crop edge.
- Enter animation classes must stay applied for the full keyframe duration. Removing an `is-entering` class on the next `requestAnimationFrame` collapses a fade/scale/slide animation into a barely visible snap.
- Don't rely on `order` to move children of a `display: contents` wrapper across flex lines in a wrapping container — Chrome's line-packing goes haywire (items land mid-line, overlapping other rows). Give the wrapper a real box (`display: block`) and order the wrapper itself instead.
- 3D-flip wrappers around content containing absolutely-positioned descendants (mega panels) silently re-anchor them: `transform`, `perspective`, `position: relative`, and (in Chrome) `transform-style: preserve-3d` on an ancestor all create a containing block. Gate every one of those properties behind an "actively animating" state class (`.is-flipping`) so at rest the wrapper is inert and panels keep anchoring to the header.
- Don't build underlines with `box-shadow: 0 2px 0 0`. When the element sits at a fractional x-position (fluid layouts guarantee this), the shadow knockout leaves a 1px vertical seam at the element's left edge. Use an absolutely-positioned `::after` bar instead — it also allows independent hover/active underline colours.
- The `flex-row()` mixin must set `flex-direction: row` explicitly. In mobile-first components the base styles apply `flex-col()` (column), and a desktop `flex-row()` override that only sets `display: flex` inherits the column direction — the nav menu rendered stacked at desktop until the mixin reset the direction.
- Percentage-height decorative pseudos on the header track content-driven growth. The overlay nav's `::before` scrim (`height: 200%`) was sized against the idle bar, but under `no-js` the fallback menu expands *inside* the header — the scrim computed to 5146px, veiled the whole page in 35% black + blur, and its overflow added ~3900px of phantom document scroll. Scope such overlays to `.js` (like the rest of the overlay machinery) or derive their size from a fixed value, never from a container whose height any state can grow.
- Scroll-linked JS transforms (`scroll` → rAF → `style.transform`) visibly lag native scrolling — browsers scroll on the compositor thread, so the JS write lands a frame or more late and the element "swims" against content that scrolls natively. To lock an element to the page/another scrolling element, put it IN the scrolling layer (e.g. an absolute full-viewport wrapper anchored to the container's first 100svh, like `.hero__follow`/`.hero__content`) and let the browser move it. A sticky sibling + scroll-layer sibling also reproduce "move together while pinned, freeze after" for free — the JS emulation (`heroTop - frameTop`) is only needed for non-1:1 factors like parallax.
- Grid columns are `minmax(0, 1fr)`, never bare `1fr`. Bare `1fr` is `minmax(auto, 1fr)`, whose `auto` floor is the column's min-content. On iPad WebKit an orientation flip does NOT reliably recompute a grid item's min-content when that item's layout changed across the breakpoint being crossed — so a stale floor sticks and inflates a track. Reproduced on the homepage 3-up card row: the trailing card in the 960–1199 horizontal band is `flex-direction: row` with a ~50% `.card__media` basis; flipping into `lg` (3-up) left that column's track at 707px (others 449px) and overflowed the row — intermittently, because it only happens when you flip FROM the band INTO the wider layout. Chromium never reproduces it. `minmax(0, 1fr)` floors the track at 0, so stale min-content can't inflate it; the layout stays equal fresh and post-flip. The bento grid was already `minmax(0, 1fr)` and was immune. Verified with a Playwright-WebKit orientation-flip harness (40 flips × 3 iPad sizes: 20 broken cycles → 0).
- The reset's `ul[class], ol[class] { padding: 0 }` is specificity (0,1,1) — element + attribute — so it OUTRANKS any single-class component rule trying to set padding on a classed list, and the declaration is dropped silently with no warning. It bit the client-logos marquee: the trailing `padding-right` that makes each copy self-contained never applied, so the seam between the two copies sat at 0 while every other gap was `--space-xl`. Use `margin` instead (`* { margin: 0 }` is (0,0,0), so a single class wins), or raise specificity to `ul.the-class`. Suspect this whenever a padding on a `ul`/`ol` with a class appears to do nothing — check the computed value rather than trusting the source.
- `overflow: hidden` STILL MAKES A SCROLL CONTAINER. It hides the scrollbar, it does not remove the scrollability: `scrollTop` is settable, and `scrollIntoView` — which every in-page anchor click performs — scrolls EVERY scrollable ancestor, not just the pane you meant. With no scrollbar the user cannot undo it. On the design-system shell that meant an anchor click nudged `.ds-app` down ~78px and the top bar and sidebar head were gone for good. Use `overflow: clip` for a box that must never scroll — it is not a scroll container at all, so nothing can move it. NOTE the interaction with the entry below: `position: relative` on the shell CONTAINS the stray absolutely-positioned descendants (stopping them inflating the document) but that hands their overflow to the shell, which is then scrollable if it is `hidden` — fixing the first bug created the second. The pair you want is `position: relative` + `overflow: clip`. (Hero panels are the opposite case — see the `overflow: hidden` not `clip` entry above; there the concern is compositor clipping of a GPU layer, not scrollability.)
- `overflow: hidden` does NOT clip an absolutely-positioned descendant whose containing block is OUTSIDE the clipping box — overflow only clips what the box actually contains. `visually-hidden` is `position: absolute` with no offsets, so it sits at its static position and, with no positioned ancestor, resolves against the ROOT: it escapes every `overflow: hidden` above it and adds its own depth to `documentElement.scrollHeight`. In the design system's 100dvh app shell that made the document 21,338px tall in a 1,116px viewport, so clicking a sidebar anchor (or any `scrollIntoView`/focus — they scroll EVERY scrollable ancestor, not just the intended pane) scrolled the window too and pushed the top bar off-screen with no way back. Fixed twice now — `.ds-segment`, then `.download__link` — so the rule: **give any element hosting a `visually-hidden` child a `position: relative`**, and keep the `position: relative` guard on `.ds-app` so a future component cannot escape the shell. Diagnose with `documentElement.scrollHeight` vs `clientHeight`: if the root scrolls on that page at all, something has escaped. Note `body.scrollHeight` stays correct, so check the ROOT.
- The angle-badge geometry (hero shape as corner badge) assumes the badge is ONE line tall: the 45° diagonal is sized to meet the bottom edge at single-line height, so a wrapped two-line label leaves the diagonal stopping partway with a vertical stub below it — and wrap/unwrap reflow during the width-swap animation makes the badge jump vertically. Keep `white-space: nowrap` on angle-badge labels and enforce label length editorially; never "fix" an overflowing label by allowing wrap. If a layout change narrows the badge's stage (e.g. splitting a section into columns), check the longest label still fits one line first — this is what reverted the feature banner's sm-band split.
- The global reduced-motion kill (`*, *::before, *::after`) does NOT reach other pseudo-elements — a transition declared on `::details-content` (the accordion) survived it. Give such pseudos their own STANDALONE `prefers-reduced-motion` rule in the component. Never add an exotic pseudo-element to the reset's shared selector list: a browser that doesn't recognise it drops the ENTIRE list, silently disabling the site-wide kill everywhere.
- A scrim/overlay that must reach the BOTTOM of a taller-than-viewport section must anchor to that section (`bottom: 0` inside `.hero`), not to a 100svh companion layer. The hero's `__follow` layer is only 100svh, but the shape panel overhangs the first viewport, so its base IS the hero's base — below 100svh. The `.hero__blur` scrim, pinned to the follow layer's bottom, therefore stopped ~220px short of the hero base below the nav breakpoint, exposing a strip of un-blurred video (desktop hid it: the follow layer is `sticky`, so its bottom rides down to the hero base at the end of the journey). Anchoring the blur to `.hero` with `top: 46svh; bottom: 0` fixes every regime, and because the base sits below the viewport until the hero scrolls off, the desktop pinned-to-viewport-bottom look is preserved for free. Use a length-based mask ramp (`black 31svh`, not `58%`) so "opaque by ~77svh" holds regardless of the now-variable band height.
- An element whose hidden state comes from the UA SHEET — `[hidden]`, a closed `[popover]` (`[popover]:not(:popover-open) { display: none }`), a closed `<details>` panel — is silently un-hidden by ANY author `display` on it, because author rules beat UA rules in the cascade regardless of specificity. Bitten twice in one week: `card.hidden = true` did nothing under the card's `display: flex` (news filter demo — worked around with `style.display`), then a popover panel skinned with `display: grid` rendered permanently IN FLOW inside the header band while `:popover-open` was false. If a component sets `display` on such an element, it must also restate the hidden state at author level (`&[hidden] { display: none }`, `&:not(:popover-open) { display: none }`). Bonus on the popover form: in engines without popover support `:popover-open` is an unknown pseudo-class, so the guard rule is dropped whole and the panel stays visible in flow — which is exactly the graceful fallback wanted there.
- Any filter, search or faceted listing needs an EMPTY STATE, and it is not optional polish — it is the difference between "no results" and "broken". The news landing's type pills could select a type with no content (entirely possible in production, where the options come from a taxonomy and a term may hold nothing): every card went `display: none`, the grid collapsed to zero height, and the page showed a blank gap with the pager still offering eight pages underneath it. A `aria-live` status announcing "0 of 13" covered screen reader users and hid the gap from testing — sighted users got nothing. Ship the empty message and HIDE THE PAGER with it (an empty result set has no pages). Keep the message out of the live region so it doesn't double up with the status string for anyone running both. In Drupal this is the view's "No results behavior" area, so the static template is standing in for a server behaviour — build it anyway, or the design never gets reviewed.
